# chocoZAP領収書からfreee取引を登録

`/Users/natsuya/workspace/invoice-bandit` でchocoZAPの領収書を取得し、freee会計へ支出取引を登録する。PDFに記載された購入日を取引日・決済日に使い、PDFの宛名を備考に記録する。

## PDF取得と内容確認

1. 依頼が `choco1` か `choco2` かを確認して、リポジトリ直下で対応する `make choco1` または `make choco2` を実行する。どちらか不明なら実行しない。
2. 標準出力に表示されたPDFの絶対パスを正とし、ファイルの存在とサイズを確認する。
3. PDFを読み、次の値を確定する。
   - `購入日`：`yyyy-mm-dd` の取引日・決済日
   - `合計金額`：取引金額
   - `宛名`：`様` の直前の氏名
   - 税額と税率
4. 宛名から空白をすべて除去する。備考は必ず `YYYY.MM.DD 氏名` とする。例：`2026.08.18 庄司佑`。
   - 氏名を固定しない。choco1・choco2それぞれのPDFから毎回読み取る。
   - `（取引日）`などの文字列を追加しない。
   - PDFの発行日を購入日の代わりに使わない。

## freeeファイルボックスへの送信

1. Gmailコネクタで、PDFを既定のfreeeファイルボックス宛 `1485229230+yux4@mail-receiver.freee.co.jp` に新規メールとして添付送信する。ユーザーが別の宛先を指定した場合は指定を優先する。
2. 送信前に宛先、件名、PDF名、サイズを示し、ユーザーが明示的に送信を依頼した場合だけ送る。
3. 送信後、freee MCPで当日のファイルボックスを取得し、送信後に増えた `origin=mail` のPDFを1件に特定する。候補が複数の場合は取引登録を止める。

## 取引登録

1. `freee_auth_status` と `freee_get_current_company` で認証状態と事業所を確認する。
2. 同じchocoZAP会費の直近取引を取得し、取引先・勘定科目・品目・税区分・決済口座を確認する。IDを推測や固定値で使わない。
3. 購入日・取引先・金額・PDF宛名が一致する取引を検索する。さらに対象Receipt IDが既に紐付いていないか確認する。同日・同額でも宛名またはReceipt IDが異なるchoco1/choco2の取引は別取引として登録する。
4. 重複がなければ `POST /api/1/deals` で、次を満たす支出取引を作成する。
   - `issue_date` と支払行の `date` はPDFの購入日
   - 金額と税区分はPDFと既存chocoZAP取引の確認結果に一致
   - 明細行の `description` は `YYYY.MM.DD 氏名`
   - 送信済みのReceiptを `receipt_ids` で紐付ける
   - MCP経由の登録を識別するメモタグ `freee-mcp` を付与する。タグがなければ、取引作成前に作成する
5. 作成後、取引を再取得して、日付、金額、備考、Receipt紐付け、決済状況、メモタグを確認する。

## 失敗時

- PDFから購入日・金額・宛名のいずれかを確定できない場合は取引を作成しない。
- freeeファイルボックスの対象PDFを1件に特定できない場合は取引を作成しない。
- 送信結果や取引作成結果が不明な場合は自動再送・自動再作成しない。

## 報告

完了時は、PDF名、購入日、備考、取引ID、Receipt ID、取引登録の確認結果を短く報告する。
